--- PAGE 4 ---
El “JPEG del 3D”
Formato glTF / .glb
Antes · .OBJ / .FBX
Exportar a la web era un dolor de cabeza con 
formatos pesados.
Hoy · glTF
GL Transmission Format: estándar abierto 
diseñado para que los navegadores lo lean rápido.
Usaremos .glb, la versión binaria: empaqueta geometría, texturas y animaciones en un solo archivo, como un .zip 
súper comprimido.


--- PAGE 5 ---
¿Por qué glTF es tan rápido?
Imagina comprar un Armario de ropa.
Formatos Viejos · .FBX
Meter un Armario ya Armado: ocupa todo el camión 
de mudanza, es pesado y cuesta meterlo por la 
puerta.
Formato .glb · IKEA
Desarmado y empaquetado al vacío en cajas 
planas: pesa muy poco. El navegador lo recibe y el 
procesador lo “arma” en milisegundos, 
directamente en la memoria de la tarjeta gráfica.


--- PAGE 6 ---
Capturando la luz del mundo real
IBL (Iluminación Basada en Imágenes) usa una fotografía panorámica de 
un lugar real para lograr reflejos 100% realistas.
Usamos HDRI (High Dynamic Range Imaging) o Environment Maps.
JPG normal
Solo guarda color.
HDRI
Guarda intensidad lumínica 
matemática.
El sol emite miles de veces más energía que el cielo azul. Three.js usa esa 
energía para iluminar el modelo.


--- PAGE 7 ---
Entendiendo el HDRI
Imagina a un actor en un teatro oscuro.
En vez de 50 linternas para simular un bosque, muy 
costosas para el procesador, lo colocamos dentro 
de una pantalla LED circular de 360 grados que 
muestra un bosque brillante.
La luz de la pantalla lo ilumina perfectamente. ¡Eso 
es el HDRI!


--- PAGE 8 ---
Magia visual a costo cero (MatCaps)
HDRI consume recursos. Para celulares de gama baja usamos MatCaps (Material Capture).
Materiales PBR (Physically Based 
Rendering (Renderizado Basado en 
Físicas)
Una cara limpia con luces de estudio reales: alto 
consumo. es el estándar de la industria que simula 
matemáticamente cómo la luz del mundo real 
interactúa con las superficies (calculando valores como 
qué tan metálico o rugoso es un objeto). En lugar de 
"pintar" o fingir los brillos, el motor gráfico calcula la 
física real de la luz rebotando en el material.
TAl tener que calcular cómo la luz incide, rebota y 
genera sombras en tiempo real para lograr 
fotorrealismo, esta técnica exige un alto consumo de 
recursos de procesamiento de la tarjeta gráfica (GPU).
MatCap · Maquillaje
Una imagen plana con sombras oscuras y brillos claros 
“finge” luces. El motor no calcula ninguna luz: envuelve 
el modelo con esa imagen.
¡Un truco óptico ultra ligero!

Paso 3: Construyendo el Set de Grabación
(Abre el archivo src/main.js, borra TODO el texto que tenga y escribe esto) No podemos meter un actor si no hay un 
set, una cámara y alguien grabando.
import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';
import { RGBELoader } from 'three/examples/jsm/loaders/RGBELoader.js';
// 1. Configuramos Escena, Cámara y Renderizador
const canvas = document.querySelector('#bg');
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 1000);
camera.position.z = 5; // Alejamos la cámara para poder ver
const renderer = new THREE.WebGLRenderer({ canvas: canvas });
renderer.setSize(window.innerWidth, window.innerHeight);


--- PAGE 15 ---
Paso 4: Cargando el Cielo Fotográfico (HDRI)
(Continuamos en main.js) Usaremos RGBELoader para leer nuestro archivo de rango dinámico y envolver nuestra 
escena con luz realista.
// 2. Cargamos el mapa de iluminación (HDRI)
const rgbeLoader = new RGBELoader();
rgbeLoader.load('/textures/bosque.hdr', (environmentMap) => {
    // Configuramos la imagen para que sea una esfera 360°
    environmentMap.mapping = THREE.EquirectangularReflectionMapping;
    // Lo aplicamos como fondo visual y como luz global
    scene.background = environmentMap;
    scene.environment = environmentMap;
});


--- PAGE 16 ---
Paso 5: Cargando el Modelo 3D (.glb)
(Continuamos en main.js) Usamos GLTFLoader para "desempaquetar" el archivo. Es asíncrono, por lo que el modelo 
aparecerá cuando termine de descargar.
// 3. Cargamos el modelo 3D
const gltfLoader = new GLTFLoader();
let miPersonaje = null; // Variable global para poder animarlo luego
gltfLoader.load('/models/robot.glb', (gltf) => {
    miPersonaje = gltf.scene; // Extraemos la geometría
    // Ajustamos tamaño y lo colocamos en la escena
    miPersonaje.scale.set(3, 3, 3);
    miPersonaje.position.y = -1;
    scene.add(miPersonaje);
});


--- PAGE 17 ---
Paso 6: El Bucle de Animación
(Al final de main.js) Si no le decimos a Three.js que tome "fotos" de la escena 60 veces por segundo, la pantalla se quedará paralizada.
// 4. Bucle de Animación
function animate() {
    requestAnimationFrame(animate);
    // Si el modelo ya cargó, lo hacemos rotar
    if (miPersonaje) {
        miPersonaje.rotation.y += 0.01;
    }
    // Tomamos la foto y la mostramos en pantalla
    renderer.render(scene, camera);
}
// ¡Iniciamos el bucle!
animate();
Punto de Control: Guarda los archivos. ¡Tu modelo ya debe verse en pantalla rotando de forma fotorrealista!

BONUS
Bonus 2: Levitación y el Bucle Final
¿Y si hacemos que el robot parezca estar flotando o respirando? Usando una simple función matemática (Seno), podemos crear un efecto de levitación súper profesional.
3. Actualizamos el bucle de animación
Reemplaza tu función animate() actual por esta versión final.
function animate() {
    requestAnimationFrame(animate);
    if (miPersonaje) {
        // 1. Rotación constante
        miPersonaje.rotation.y += 0.01;
        // 2. ¡Efecto de levitación usando matemáticas!
        // Date.now() crea el tiempo, Math.sin hace que suba y baje suavemente
        miPersonaje.position.y = Math.sin(Date.now() * 0.002) * 0.5 - 1;
    }
    // 3. Actualizamos la inercia de la cámara en cada frame
    controls.update();
    // 4. Tomamos la foto y la mostramos
    renderer.render(scene, camera);
}
activamos la rotación con el clic izquierdo rpesionado, se movera alrededor del robot el cual esta con una animación de flote:
con clic derecho presionado ubicaremos libremente la camara.
con el scroll + o scroll + alejamos o acercamos la camara

Tips Pro para Entornos Multimedia
Compresión DRACO
En proyectos reales, los .glb se 
comprimen con Draco, un algoritmo 
de Google.
20MB → 2MB
Resolución de Texturas
Una textura 4K arruinará la 
experiencia web. Para móviles, 
máximo 1024x1024 o 2048x2048.
Limitar HDRIs
Pueden pesar muchísimo. 
Herramientas web los comprimen 
conservando los datos de luz 
importantes, sin pérdida visual 
notable.
