Concepto 1 — ¿Por qué un Motor de Físicas?
Animación Cinemática vs. Simulación Física
Animación Manual (Cinemática)
Modificar mesh.position.y -= 0.1 en cada frame.
Problema: No contempla aceleración, peso, inercia ni reacción 
ante obstáculos. El movimiento es lineal, artificial y no escala a 
escenas complejas.
Simulación Física (Dinámica)
Delegar el cálculo del movimiento a un motor matemático 
basado en F = m · a.
Ventaja: El motor calcula trayectorias, rebotes, fricción y 
colisiones complejas de forma orgánica y automática.
Sin Motor Físico
Posición actualizada 
manualmente
Sin aceleración real
Sin rebote ni fricción
Colisiones imposibles de 
escalar
Con Motor Físico
Ecuaciones de Newton 
integradas
Gravedad, inercia y 
torque
Rebote y fricción 
configurables
Colisiones automáticas y 
precisas

Concepto 3 — El Bucle de Simulación (Fixed 
Time Step)
Cómo computa el tiempo el motor físico
1 El Problema de los FPS Variables
Las pantallas corren a tasas de refresco variables: 60 Hz, 120 
Hz, 144 Hz. Si la física dependiera de los FPS de la pantalla, un 
juego iría al doble de velocidad en un monitor de 144 Hz.
2 El Paso de Tiempo Fijo (World.step)
Definimos un delta de tiempo constante, típicamente 1/60 de 
segundo (≈ 0.0166 s). Esto desacopla la física de la tasa de 
refresco del monitor.
3 Resultado: Consistencia Universal
El método world.step(1 / 60, deltaTime, 3) actualiza las 
ecuaciones de movimiento de forma uniforme en cualquier 
dispositivo.
Fórmula del Paso 
Fijo
t_físico = 1/60 segundos
≈ 0.0166 s por iteración
Parámetros de 
world.step
1/60 — Paso fijo de 
tiempo
deltaTime — Tiempo real 
transcurrido
3 — Máx. sub-pasos por 
frame

Concepto 4 — Tipos de Cuerpos Rígidos 
(RigidBodies)
En un motor 3D, los objetos físicos se clasifican según su comportamiento frente a fuerzas:
Tipo de Cuerpo ¿Le afecta la gravedad? ¿Se mueve al colisionar? Casos de Uso Ideal
Dynamic (Dinámico) 🟢 Sí 🟢 Sí Cajas, pelotas, vehículos, proyectiles.
Static (Estático) 🔴 No 🔴 No Pisos, paredes, rampas, terreno.
Kinematic (Cinemático) 🔴 No 🟢 Solo por código Plataformas móviles, puertas automáticas.
Dynamic
mass: 1 (o cualquier valor > 0). Responde a 
gravedad y colisiones.
Static
mass: 0. Inamovible. Ideal para el entorno 
del nivel.
Kinematic
Controlado por código. No responde a 
fuerzas externas.

Concepto 5 — Geometrías de Colisión 
(Bounding Shapes)
Rendimiento vs. Precisión
El cálculo de colisión entre polígonos complejos es extremadamente costoso para la CPU. Por ello, envolvemos los modelos visuales en formas 
físicas simplificadas:
Sphere
Mínimo costo computacional. Evalúa solo radio y centro. Ideal 
para pelotas, proyectiles y objetos aproximadamente redondos.
Box
Bajo costo. Caja orientada (Bounding Box). Perfecto para cajas, 
edificios, plataformas y objetos rectangulares.
Cylinder
Costo medio. Ideal para personajes, cápsulas y objetos cilíndricos 
como barriles o columnas.
Convex
Alto costo. Aproximación por malla poligonal. Usar solo cuando la 
precisión es crítica y el objeto es convexo.
Regla de oro: usa siempre la forma más simple que aproxime razonablemente el objeto visual. El rendimiento a 60 FPS depende de ello.

Concepto 6 — Propiedades de Materiales 
Físicos
CANNON.Material y CANNON.ContactMaterial
No se refieren a colores o texturas, sino a comportamiento de superficie:
Restitución (Restitution / Bounciness)
Factor de rebote al colisionar:
0.0 = Plastilina / sin rebote (energía absorbida totalmente)
0.5 = Pelota de tenis (rebote parcial)
1.0 = Pelota de goma / rebote perfecto (energía conservada)
Fricción (Friction)
Resistencia al deslizamiento sobre la superficie:
0.0 = Hielo superresbaladizo (sin resistencia)
0.3 = Superficie normal (madera, concreto)
1.0 = Lija / agarre total (máxima resistencia)
Ejemplo de Interacción entre Dos 
Superficies
// Ejemplo de interacción entre dos superficies
const contactMaterial = new CANNON.ContactMaterial(
    pisoMaterial, pelotaMaterial,
    { friction: 0.3, restitution: 0.7 }
);
El ContactMaterial define el comportamiento cuando dos 
materiales específicos entran en contacto. Se puede tener 
múltiples combinaciones en la misma escena.

Concepto 7 — Detección de Colisiones y 
Eventos
Fases del Algoritmo de Colisión
Broadphase
Fase Ancha. Filtra rápidamente qué objetos 
están lejos y descarta parejas imposibles de 
colisionar. Optimización crítica de 
rendimiento.
Narrowphase
Fase Estrecha. Evalúa el contacto exacto 
punto a punto de los objetos cercanos 
restantes. Alta precisión matemática.
Evento 'collide'
Escuchadores de Eventos. Disparar lógica 
multimedia: reproducir sonido 3D, emitir 
partículas o cambiar el color del objeto en 
colisión.
Ejemplo de Escuchador de Colisión
body.addEventListener('collide', (event) => {
// Reproducir sonido, emitir partículas, cambiar color...
const impactVelocity = event.contact.getImpactVelocityAlongNormal();
if (impactVelocity > 1.5) playImpactSound();
});

Laboratorio Paso 2 — Escena, Cámara y 
Luces
Código en main.js (Parte 1):
import * as THREE from 'three';
import * as CANNON from 'cannon-es';
// 1. Escena, Cámara y Renderizador
const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 100);
camera.position.set(0, 5, 10);
camera.lookAt(0, 0, 0);
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(window.innerWidth, window.innerHeight);
renderer.shadowMap.enabled = true; // Activa el cálculo de sombras
document.body.appendChild(renderer.domElement);
// 2. Iluminación
const ambientLight = new THREE.AmbientLight(0xffffff, 0.5);
scene.add(ambientLight);
const dirLight = new THREE.DirectionalLight(0xffffff, 1);
dirLight.position.set(5, 10, 5);
dirLight.castShadow = true; // Permite proyectar sombras sobre el suelo
scene.add(dirLight);
💡 Explicación Didáctica para la Clase:
PerspectiveCamera: Imita el ojo humano (campo de visión de 75° y perspectiva de profundidad).
camera.lookAt(0,0,0): Apunta el lente de la cámara exactamente al centro del suelo tridimensional.
shadowMap.enabled = true: Sin este parámetro, las sombras no se calculan y los objetos parecen "flotar" sin sentido de 
profundidad.

Laboratorio Paso 3 — Gravedad y 
Materiales de Contacto
Código en main.js (Parte 2):
// 1. Creación del Mundo Físico
const world = new CANNON.World();
world.gravity.set(0, -9.82, 0); // Simulación de la gravedad en m/s² (Eje Y)
// 2. Definición de Propiedades Físicas (Fricción y Elasticidad)
const defaultMaterial = new CANNON.Material('default');
const contactMaterial = new CANNON.ContactMaterial(
    defaultMaterial, 
    defaultMaterial,
    { 
        friction: 0.4,    // Resistencia al deslizamiento
        restitution: 0.7  // Coeficiente de rebote (0 = Plastilina, 1 = Pelota de goma)
    }
);
world.addContactMaterial(contactMaterial);
world.defaultContactMaterial = contactMaterial;
💡 Explicación Didáctica para la Clase:
world.gravity.set(0, -9.82, 0): Define la fuerza hacia abajo en el eje vertical Y.
restitution: 0.7: Controla la energía que conserva el objeto al colisionar. Un valor de 0.7 genera un rebote elástico realista sin ser 
infinito.

Laboratorio Paso 4 — Construcción del 
Plano Base
Código en main.js (Parte 3):
// --- SUELO FÍSICO (CANNON.ES) ---
const groundShape = new CANNON.Plane();
const groundBody = new CANNON.Body({ mass: 0, material: defaultMaterial }); // Masa 0 = Objeto inamovible
groundBody.addShape(groundShape);
groundBody.quaternion.setFromEuler(-Math.PI / 2, 0, 0); // Rotar -90 grados en X
world.addBody(groundBody);
// --- SUELO GRÁFICO (THREE.JS) ---
const groundMesh = new THREE.Mesh(
    new THREE.PlaneGeometry(20, 20),
    new THREE.MeshStandardMaterial({ color: 0x222222 })
);
groundMesh.rotation.x = -Math.PI / 2; // Orientar paralelo al suelo físico
groundMesh.receiveShadow = true;
scene.add(groundMesh);
💡 Explicación Didáctica para la Clase:
¿Por qué dos suelos?: Three.js dibuja lo que se ve (groundMesh), mientras que Cannon.es calcula dónde rebotan las cosas 
(groundBody).
mass: 0: Le indica al motor matemático que este cuerpo no cae ni se mueve cuando un objeto pesado lo golpea.
quaternion.setFromEuler(-Math.PI / 2, 0, 0): Por defecto los planos en 3D están verticales (como paredes). Los rotamos 90° para 
dejarlos horizontales.

Laboratorio Paso 5 — Sincronización de 
Coordenadas
Código en main.js (Parte 4):
const objectsToUpdate = []; // Colección de pares { mesh, body }
const clock = new THREE.Clock();
let oldElapsedTime = 0;
function animate() {
    requestAnimationFrame(animate);
    const elapsedTime = clock.getElapsedTime();
    const deltaTime = elapsedTime - oldElapsedTime;
    oldElapsedTime = elapsedTime;
    // 1. Avanzar la simulación física (paso de tiempo fijo a 60 FPS)
    world.step(1 / 60, deltaTime, 3);
    // 2. Copiar la posición y rotación matemática de Cannon a las mallas de Three
    for (const object of objectsToUpdate) {
        object.mesh.position.copy(object.body.position);
        object.mesh.quaternion.copy(object.body.quaternion);
    }
    renderer.render(scene, camera);
}
animate();
💡 Explicación Didáctica para la Clase:
world.step(1 / 60, ...): Cannon.es calcula dónde debe estar cada objeto en el siguiente milisegundo.
object.mesh.position.copy(...): El "puente" que une la física con los gráficos. Mueve el modelo 3D visible exactamente a donde 
Cannon dice que cayó el objeto invisible.

Laboratorio Paso 6 — Creación Dinámica 
de Esferas
Código en main.js (Parte 5):
function createSphere(radius, position) {
    // 1. Malla Gráfica
    const mesh = new THREE.Mesh(
        new THREE.SphereGeometry(radius, 32, 32),
        new THREE.MeshStandardMaterial({
            color: Math.random() * 0xffffff, // Color aleatorio
            roughness: 0.2
        })
    );
    mesh.castShadow = true;
    mesh.position.copy(position);
    scene.add(mesh);
    // 2. Cuerpo Físico
    const shape = new CANNON.Sphere(radius);
    const body = new CANNON.Body({
        mass: 1, // Objeto dinámico con peso
        shape: shape,
        position: new CANNON.Vec3(position.x, position.y, position.z)
    });
    world.addBody(body);
    // 3. Vincular para actualización continua
    objectsToUpdate.push({ mesh, body });
}
💡 Explicación Didáctica para la Clase:
Math.random() * 0xffffff: Genera un color HEX distinto para cada esfera que el usuario lanza.
objectsToUpdate.push({ mesh, body }): Registra la pareja en la lista para que la función animate() sepa que debe sincronizar este 
nuevo objeto en cada fotograma.

Laboratorio Paso 7 — Disparador Clic y 
Ajuste Responsivo
Código en main.js (Parte 6):
// Evento: Lanzar esfera al hacer clic
window.addEventListener('click', () => {
    createSphere(
        0.4 + Math.random() * 0.3, // Radio variable entre 0.4 y 0.7
        {
            x: (Math.random() - 0.5) * 3, // Dispersión horizontal X
            y: 8,                         // Caída desde altura Y = 8
            z: (Math.random() - 0.5) * 3  // Dispersión profundidad Z
        }
    );
});
// Evento: Reajuste automático de pantalla
window.addEventListener('resize', () => {
    camera.aspect = window.innerWidth / window.innerHeight;
    camera.updateProjectionMatrix();
    renderer.setSize(window.innerWidth, window.innerHeight);
});
💡 Explicación Didáctica para la Clase:
(Math.random() - 0.5) * 3: Hace que las esferas no caigan exactamente en la misma coordenada, permitiendo que colisionen entre 
ellas al llegar al suelo.
